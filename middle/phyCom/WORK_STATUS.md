# 피지컬 컴퓨팅 수업자료 개발 현황

이 문서는 현재 변동되는 개발 상태와 검증 결과를 기록한다. 지속 적용할 작업 원칙은 `WORK_RULES.md`를 따른다.

## Git 및 확인 기준
- 작업 브랜치: 원격 `main`
- 현재 문서 및 코드 대조 기준 원격 HEAD: `68a44fd86b699e630931445afddbad2d133e9736` (`Add physical computing work rules and status`)
- 이 작업공간에는 저장소 체크아웃이 없어 로컬 브랜치·HEAD·status는 확인할 수 없다. GitHub 원격 `main`의 커밋과 파일을 기준으로 확인했다.
- 두 관리문서는 기준 HEAD에 이미 존재한다. 해당 HEAD의 GitHub Pages 빌드는 성공했다.
- `led/index.html`, `common/css/slides.css`, `common/js/slides.js`의 현재 원격 `main` 내용을 정적으로 확인했다. CSS 계산값과 DOM 조건은 확인할 수 있지만, 코드만으로 화면의 실제 겹침·잘림을 확정하지 않는다.

> 기준 HEAD는 복구 가능한 코드 기준일 뿐, 정상 동작이 검증된 안전 기준점은 아니다.

## 현재 개발 위치
- 단원: LED
- 작업 위치: 엔트리 화면의 장면·오브젝트 추가 안내 단계

## 현재 구현 상태 — 정적 코드 대조

### 장면 생성과 장면 2 번호
- `sceneStep` 1에서 장면 2 탭을 표시하고 장면 2와 오브젝트 추가 버튼을 안내한다.
- 장면 2 탭의 번호 `1`은 CSS 가상요소 `::after`로 표시된다. 앞쪽 CSS 규칙의 위치값은 후속 규칙에 덮이며, 파일 마지막 관련 위치 규칙은 탭을 기준으로 `left: 8px; top: 4px`이다. 오브젝트 추가 버튼의 번호 `2`는 `left: 8px; top: -30px`로 지정되어 있다. 실제 화면에서 글자와 겹치는지, 강조 테두리 안팎에서 어떻게 보이는지는 배포 화면 검증이 필요하다.
- HTML에는 후속 단계용 `.setup-number` 요소 8개와 오브젝트 창 안의 원형 `.setup-object-number` 요소 3개가 있다. CSS `::after`/`::before` 가상요소도 별도의 네모형 단계 번호를 만든다.

### 오브젝트 창, 검색, 결과
- 기본 안내 흐름에서 단계 2~4 동안 오브젝트 창이 열린다. `updateScene()`은 수동 창 조작이 아닐 때 단계 2 이상에서 검색칸에 `LED`를 넣고, 검색어에 `LED`가 포함될 때 네 가지 LED 결과를 표시한다.
- 수동으로 오브젝트 추가 버튼을 눌러 창을 연 경우에는 검색어를 비우고 선택 상태도 초기화한다. 이 경로에서는 검색어를 입력하기 전까지 결과 목록이 숨겨진다.
- 검색칸 강조와 `대문자 LED로 검색하세요` 안내의 CSS에는 단계별 규칙뿐 아니라 창이 열려 있으면 적용되는 공통 규칙이 있다. 기본 흐름에서 창이 열리는 단계 2·3·4 모두 검색칸과 검색 안내에 관련 스타일이 적용된다. `led-search-tip` 요소는 숨김 처리되고 창 안의 `led-search-callout`이 사용된다. 여러 단계에 계속 안내·강조가 나타나는 것이 의도된 수업 흐름인지는 검토 및 배포 화면 확인이 필요하다.

### 노란 LED 선택, 미리보기, 추가하기
- 기본 안내 흐름은 `sceneStep`이 4가 될 때 JavaScript에서 `selectedLed=4`로 설정한다. 따라서 단계 4는 노란 LED 항목이 선택된 상태로 그려진다. 수동 창 경로에서는 창을 열 때 `selectedLed`를 `null`로 초기화하며, 항목을 누른 뒤 선택 상태가 설정된다.
- 오른쪽 `#objectSelectedPreview`는 `selectedLed`가 참일 때만 표시되고, 선택 개수는 1로 바뀐다. 선택 전에는 미리보기가 숨겨지고 개수는 0이다. 기본 안내 흐름의 단계 4에서는 자동 선택으로 미리보기가 보이며, 수동 경로에서는 LED 항목을 선택한 뒤 보인다.
- 노란 LED 항목은 단계 4에서 CSS로 강조된다. 추가하기 버튼도 창이 열려 있는 동안 공통 CSS 강조를 받으며, 선택값이 없으면 JavaScript가 버튼을 비활성화한다. 단계 4에는 항목과 추가하기 버튼을 강조하는 별도 단계 규칙도 있다. 선택과 추가 안내가 한 단계에 겹치는 것이 적절한지는 설계 검토 및 배포 화면 검증이 필요하다.
- 선택 항목을 누르면 `selectedLed`가 설정되고 단계는 최소 4가 된다. 추가하기를 누르면 선택값을 `chosenLed`로 옮기고 단계 5로 진행하며 창을 닫는다.
- 전진은 다음 버튼 또는 `ArrowRight`·`PageDown`·스페이스 키에서 `advanceSetup()`으로 처리한다. 후진은 이전 버튼 또는 `ArrowLeft`·`PageUp` 키에서 `previousSetup()`으로 처리한다. 단계 5에서 4로 돌아가면 선택값을 복원하고, 단계 4에서 3으로 돌아가면 선택값을 비운다. 수동으로 창을 연 동안 전진은 창을 닫고 다음 단계로 가며, 후진은 우선 창을 닫는다. 실제 배포 화면의 왕복 동작은 검증되지 않았다.

### 번호 표시, 누적 및 잘림 가능성
- 오브젝트 창에는 원형 번호 DOM 요소 1~3이 있고, 검색칸·노란 LED·추가하기 버튼에는 CSS 가상요소로 네모형 번호가 추가된다. 단계 2와 3에서는 원형 번호 요소 1이 표시되고 검색칸에도 가상 번호 1이 지정된다. 단계 4에서는 원형 번호 1~3과 검색칸·노란 LED·추가하기 버튼의 가상 번호 1~3이 함께 표시되도록 CSS가 구성되어 있어 번호 중복 가능성이 있다.
- 단계 4에서 번호 요소 1이 이전 단계부터 유지되고 2·3이 더해지는 누적 표시 규칙이 있다. 누적 방식이 의도된 안내인지와 실제 화면의 중복·가독성은 검증되지 않았다.
- 노란 LED 번호 가상요소는 해당 버튼 기준 `left: -10px; top: -12px`에 배치된다. 버튼에는 `overflow: hidden`이 지정되어 번호 일부가 잘릴 가능성이 있다. 실제 배포 화면에서 확인이 필요하다.
- 장면 2와 오브젝트 창 모두 DOM 번호와 CSS 가상요소 번호 체계가 함께 존재한다. CSS 파일 후반부에 같은 대상에 대한 중복 규칙과 `!important` override가 누적되어 있어 최종 시각 결과와 유지보수성 검토가 필요하다.

## 확인된 기술부채 및 미검증 설계
- 번호 DOM 요소와 가상요소 번호 방식이 혼재하고, 단계 2~4에서 번호가 중복될 가능성이 있다.
- 단계 2~4에 검색 강조·안내가 이어지고 단계 4에는 선택 및 추가하기 강조도 함께 적용된다. 검색 → 노란 LED 선택 → 오른쪽 미리보기 → 추가하기의 안내 순서와 강조 시점을 검토해야 한다.
- 노란 LED 번호는 `overflow: hidden`의 영향을 받을 수 있다.
- `common/css/slides.css` 후반부에 번호 위치, 검색 안내, 선택·추가 강조의 중복 규칙과 override가 여러 차례 있다. `.led-search-tip`은 숨겨지고 `.led-search-callout`이 사용된다.
- 관련 단계·상태·이벤트는 `common/js/slides.js`에 있다. `sceneStep`, `selectedLed`, `chosenLed`, `manualSetupDialog`가 함께 상태를 제어한다. 검색 입력, LED 선택, 추가하기 및 단계 전환의 핵심 이벤트 리스너는 각 대상에 등록되어 있으며, 정적 조사에서 동일 리스너의 명확한 중복 등록은 확인되지 않았다.
- 실제 배포 화면, 번호의 최종 겹침·잘림, 단계별 강조가 수업 흐름에 적절한지, 정방향·역방향 및 화면비 변화는 검증 필요다.

## 검증 현황
- 원격 `main` 기준 HEAD 및 관련 LED HTML/CSS/JS: 정적 확인 완료.
- 기준 HEAD의 Pages 빌드: 성공 기록 확인.
- GitHub Pages 배포판에서 오브젝트 안내 단계 2~4를 일부 조작하고 DOM·계산 스타일을 확인했다. 검색어 `LED`, 검색칸 강조 및 검색 안내가 유지됐고, LED 선택 전에는 오른쪽 미리보기가 숨겨지며 단계 4에서 노란 LED 선택 후 나타났다. 추가하기 뒤 오브젝트 창이 닫히고 작업 화면에 노란 LED가 추가된 상태도 확인했다. 실제 시각적 위치·겹침·잘림을 전체 화면에서 확인한 것은 아니다.
- 역방향으로 일부 이전 단계까지 이동하여 단계 문구와 선택 수가 바뀌는 것을 확인했으나, 전체 단계 왕복 검증은 완료하지 못했다. 단계 0에서 장면 2 탭은 숨겨지는 것을 확인했다.
- 전체 슬라이드 탐색 및 처음부터 끝까지의 정방향 흐름, 전체 역방향 흐름, 반복 실행은 검증 필요.
- 전체화면, 화면 크기·화면비 변경 검증은 미완료.
- 장면 2 번호의 실제 위치·겹침, 번호의 전체 단계 중복·누적·잘림, 강조·안내의 전체 흐름은 정적 조건 일부를 확인했으며 실제 배포 화면 검증 필요.
- 내용 정확성·오개념 검토: 이번 문서 정리에서는 수행하지 않음.
- 코드·구조 최적화: CSS 중복·override 등 위 기술부채를 확인했으나 코드 정리는 수행하지 않음.
- 검증된 안전 기준점: 아직 확정되지 않음.
